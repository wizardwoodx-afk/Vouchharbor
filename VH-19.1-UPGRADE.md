# Vouch Harbor 19.1.0 "Shipyard" — upgrade notes

Base: 19.0.0 "Bastion" (460-specialist bench, domain oversight, failure
taxonomy, legacy-compat registry). 19.1.0 is the **team release**: the
workspace where domain leads — now **Captains** — take a whole brief
("build me a Y app") and run the needed domains **together**, every
provider call passes an **autonomous token optimizer**, research gets a
**live-data GuardRail**, and the 19.0.0 review's one required fix — the
multi-member aggregation path — is in. Protocol unchanged at v0.10.7.

## 1 · The Shipyard — the Team workspace

`src/vh19/shipyard.ts` + the door's Shipyard panel. One brief becomes a
**Build**: the product's own router maps it to domains, and each needed
domain gets a **work order** under its Captain (capped at 6 — focus beats
sprawl; a brief too vague to route opens one honest research order).
Orders execute one at a time through the **real Generalist pipeline** —
gate, routing, provider call, provenance digest all still apply — with
the Captain named in the order prompt. Honesty rules, probe-pinned
(`probe/shipyard`, 22 checks): only a truly executed run marks an order
`executed` (gated / refused / planned / error ⇒ `blocked`, with the real
note); a blocked order **blocks the build** and is never counted as done;
`Run all` stops at the first block; **DONE requires every order executed**
and **SETTLED seals a real 64-hex build digest** over the order results.
State is a local checkpoint (`vh19.shipyard.v1`); nothing is simulated.

## 2 · Captains — the AgentLead layer, renamed and fixed

The 19.0.0 "AgentLead" layer is renamed **Captain** (harbor metaphor:
one Generalist at the door, ten Captains, one Shipyard). `lead.code` →
`captain.code`, `AgentLead` → `Captain`, `buildLeadReport()` →
`buildCaptainReport()` (`src/vh19/captains.ts`). **The required fix from
the 19.0.0 review is in:** the Captain's report now receives the results
of **every routed specialist**, not just the first — the pipeline runs
one combined execution for the routed set and each participating member
carries that run's real outcome, honestly labelled. `probe/captains`,
27 checks (including the all-members aggregation pin).

## 3 · Autonomous token optimizer

`src/vh19/tokenOptim.ts`. Every composed system prompt is measured
(~4 chars/token, labelled as an estimate everywhere) and budget-fitted
(6,000-token default) **without being asked**: skill examples are
sacrificed before procedures, procedures before checklists, and cuts are
marked in the text itself — the optimizer never silently changes meaning.
Every provider call — optimized or not — lands in a local ledger
(`vh19.tokens.v1`, capped): calls, prompt/reply tokens, trims, savings,
shown live in the door's Shipyard strip.

## 4 · Live-data GuardRail — "always search for current and live data"

New skill `research.live-data` (bound to research **and** analysis):
search before composing for anything time-sensitive, query for freshness,
date every external claim ("as of …"), prefer the most recent primary
source, flag stale data as stale, and state knowledge-cutoff gaps
honestly. For the two time-sensitive categories the directive is not a
suggestion — `buildSpecialistPrompt()` hard-appends it to every composed
research/analysis prompt.

## 5 · Carried from 19.0.0 "Bastion"

- **Failure taxonomy** (`src/vh19/failures.ts`): every non-execution
  classified — `no-provider · provider-auth · provider-rate-limit ·
  provider-timeout · provider-unreachable · bad-response · gate-denied ·
  policy-refused · injection-blocked · peer-refused · bad-input ·
  unknown` — with severity, meaning, recovery advice, truthful retry
  verdict; attached centrally so every exit path carries it, digest-sealed.
- **Bench at 460** across 10 categories (code 68 · security 53 · devops 47 ·
  testing 45 · data 44 · research 44 · analysis 41 · writing 40 · design 40 ·
  review 34, +4 ops-prefixed), zero duplicate ids, skill-bound.
- **Legacy isolation**: `docs/LEGACY-COMPAT.md` + `probe/legacyCompat`
  enforce the compat registry in both directions; `VH_BROWSER_*` primary
  with legacy fallback; MCP client identity "vh".
