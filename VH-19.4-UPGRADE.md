# Vouch Harbor 19.4.2 "Broader" — upgrade notes

19.3.0 proved the execution machinery. 19.4.0 makes the *product* wear it:
a chat-first front door, the whole shell in one five-color premium system,
the reviewer's exact integration gap closed, and a bench wide enough to
carry real product work.

## The five-color system, made ours

The entire application — boot seal, sidebar, console, every dock — now rides
five colors and nothing else:

1. **Gunmetal** `#2D3142` — ink, primary actions, the user's voice
2. **Greyish White** `#D5DFEA` — surfaces and the agent's voice
3. **Platinum** `#D8D5DB` — the canvas
4. **Brooklyn** `#586A66` — the sage accent: success, verified, live
5. **Simple Plum** `#827278` — gates, pauses, warnings

Every hairline, muted tone, tint and shade is an alpha or mix of the five.
The old dark "atelier" theme and its bouncy loader are retired; the boot is
a quiet seal on platinum with five watching dots, reducible via
`prefers-reduced-motion`.

## The front door is a conversation

Users chat, then work. Each VH-19 reply carries its evidence inline:
routing with reasons, per-member tool receipts, the Captain's synthesis,
live-data stamps (retrieval vs disclosure, per-URL), failure classes, and
the proof digest. The human gate is a real blocking modal. Accept/reject
still feeds the memory the autonomy exam is built from.

## The reviewer's gap, closed

19.3.0's review found that the default UI never passed `workspaceRoot` /
`evidenceFetch` into `askVH19()`, so the shipped app could fall back to
toolless members. 19.4.0 wires both from the real door, and adds the
storage seam that makes browser execution honest:

- `GeneralistDeps.fsImpl` / `ToolContext.fsImpl` — Node keeps the genuine
  `node:fs/promises`; the browser door supplies a seeded virtual workspace
  (default) or a user-picked directory via the File System Access API.
- The same resolver, gate and receipts on every surface; the run's
  canonical digest states which seam it rode on (`workspace.kind`).
- Toolless remains available (Detach) and is stated, never hidden.

## Broader bench: 620 registered specialists — stated as composition

160 individually specified specialists join the 460: **460 seed-batch +
160 broader-batch = 620 registered specialists**. Both batches are fully
routable `Specialist` records in the same registry — "seed" vs "broader"
names the authoring batch (the broader batch is authored in
`broaderBench.ts` and joins via a spread, which is why counting `seed()`
calls alone misses it), not a capability difference. `catalogStats()`
reports the breakdown itself (`byProvenance`), and the door probe pins
`seed + broader === count`. **product, business, legal, comms** become
first-class categories with read-only tool bindings by design — advisors
audit, they don't mutate. Where the 460 already owned a domain, the new
entries deepen it under a distinct id (federation, lakehouse, game days,
data contracts, token architecture, …).

## App connectors — declared, gated, revocable

GitHub, Gmail, Google Calendar, Slack, Notion, Drive ship as inspectable
policy objects: one sentence of purpose, an egress prefix, declared scopes.
Connecting one binds a generated playbook skill to its bench categories;
every call still rides the existing SSRF-guarded, human-gated `net.fetch`.
No sixth tool, no silent egress.

## Skills import — OpenClaw and Hermes, one faithful parser

Both ecosystems ship the open SKILL.md (Agent Skills) format; Vouch Harbor
imports either with provenance (source, timestamp, sha-256). Gating
metadata is respected honestly: a skill needing binaries or env vars is
ineligible on surfaces that cannot verify them, and says so. Eligible
imports compose into routed specialists' prompts as playbooks — never as
capability grants.

## 19.4.1 — the 19.4.0 review, closed; BYOA; RSI

19.4.0's release review flagged four claims-vs-code gaps. Every one is closed,
and two capabilities the review set up are now real:

1. **BYOA — bring your own agent.** External agents register (name, endpoint
   kind — OpenAI-compatible or A2A JSON-RPC — model, capabilities, risk
   ceiling) and join the Generalist through the existing peer seam: the
   composer routes to the bench or to a brought agent; every delegation pauses
   at the human gate (external = hostile-adjacent) and lands in the handoff
   ledger with a receipt digest; session keys live in memory only. Inbound is
   the mirror: signed invitation + the host runtime's A2A endpoint
   (`npm run host`), receipts both ways.
2. **RSI — recursive self-improvement, the bounded kind.** After the 2026 RSI
   literature: a CURRICULUM scanned deterministically from the agent's own
   evidence ledger (rejections, gate denials, refused handoffs — nothing
   invented); an ACTOR that drafts frozen SKILL playbooks (one receipted
   provider call when wired, the raw correction otherwise); a VERIFIER
   hierarchy where human approval and the autonomy exam outrank everything
   and intrinsic self-assessment is never a verifier; memory entries are
   frozen, digest-stamped, composed into routed prompts (no parameter
   updates) and revert exactly. A floor the loop can never touch: the gate,
   the exam, the verification suites, the risk tiers, the floor itself.
3. **One network policy.** Evidence retrieval now rides the same
   `checkEgressUrl` SSRF guard as tool egress; a model-cited URL gets no
   privileges a tool call would not have, and a refusal is receipted like any
   other retrieval outcome.
4. **Count honesty.** The specialist count is stated as its composition —
   460 seed + 160 broader = 620, verifiable from `catalogStats()` — and the
   registry comment says the same.
5. **Wording honesty.** Connectors are governed connector DECLARATIONS (policy
   + playbook skills over the existing SSRF-guarded net.fetch), not OAuth
   integrations; OpenClaw/Hermes are SKILL.md ecosystem IMPORTS (the skill
   format), not runtime merges. The release-verification record now covers
   this release.

## 19.4.2 — the matured RSI framework, the BYOA trust intersection, and a self-proving count

19.4.2 answers the 19.4.1 review's one change-request ("make the RSI
curriculum cover the full declared evidence hierarchy, and tie it to the
measured mission loop") and its BYOA hardening item — built on a survey of
the 2026 RSI landscape (AlphaEvolve, Darwin Gödel Machine, Gödel Agent,
STOP, SEAL, ADAS, DSPy/TextGrad/Trace, Reflexion, Voyager, RSIAgent, plus
the two papers in the reading list). Full design: `docs/RSI-FRAMEWORK.md`.

### RSI, matured

- **Full curriculum.** All five declared evidence sources are now wired
  live: user rejection (decision ledger), human-gate denials (ingested at
  the gate), execution failures (refused/error/gated-out outcomes +
  classified failures), live-data unverified events (retrieval receipts
  that did not verify), and handoff refusals (A2A/BYOA ledger). Nothing is
  invented; every topic cites ledger evidence.
- **The promotion ladder — applied ≠ trusted.** An applied playbook enters
  as `measuring` and can only be settled by a MEASURED comparison
  (candidate beats baseline, evidence named). Losing measurements retire
  the playbook and revert its frozen memory exactly. Self-declared success
  has no API to call. Same discipline as the mission self-improve loop
  (baseline/candidate arms, adoption margin, learning receipts) — the two
  layers now share one contract: nothing is adopted on its own say-so.
- **Verifier hierarchy in code.** Human approval and the autonomy exam
  outrank everything; intrinsic self-assessment is never a verifier — the
  field's own evidence (Huang et al., ICLR 2024) says loops that verify
  themselves self-confirm and collapse.
- The floor is unchanged and probe-pinned: the loop may never touch the
  gate, the exam, the verification suites, the risk tiers, or itself.

### BYOA, hardened

- **The trust intersection**: endpoint policy (the shared SSRF/egress
  guard) ∩ risk ceiling ∩ declared capabilities (self-declared — NEVER
  authoritative) ∩ identity. Checked at registration AND re-checked at
  delegation time; a failing endpoint is refused at registration, not
  discovered mid-task. The door probe pins an SSRF endpoint failing both.

### The fleet count proves itself

The reviews counted `seed()` calls and missed the broader-batch spread.
Rather than argue, the count is now self-proving: `catalogStats()`
reports `byProvenance` computed from the arrays themselves (460 seed +
160 broader), the door renders the composition live, and the probe pins
`seed + broader === count === 620`. The docs say "620 registered
specialists (460 seed-batch + 160 broader-batch)" — both batches fully
routable; the names denote authoring lineage, not capability.
