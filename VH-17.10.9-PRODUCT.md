# VH 17.10.9 — Product Build

## Product model

VH-19 is the user-facing generalist/head. Users do not select specialists directly. The generalist routes work through a VH-owned specialist contract and MoE registry.

### Multi-user collaboration

User 1 creates a collaboration invite/message. User 2 must explicitly approve it before the collaboration becomes active. Once approved, task-scoped Team-Evolve memory may be retained for future use.

### Specialist layer

The registry ships 512 specialist entries today and is designed to grow without changing the runtime contract. Specialists carry capability, risk, permissions, benchmark score, security score, latency class, framework provenance, and version metadata.

### Team-Evolve

Team-Evolve is separate from individual agent learning. Approved collaborations can retain task-relevant successful/failed patterns and confidence as shared team memory.

### User learning

Live and exam feedback is stored as explicit preference signals: accepted/correct, rejected/wrong, and optional explanation. This is evidence for future routing and calibration, not silent global training.

### Calibration → autonomy

The agent generates relevant scenarios, supplies its proposed answer, and asks the user to mark Correct/Wrong with optional explanation. A score of 90% or higher makes the agent eligible for category-scoped autonomy; otherwise it remains supervised. Autonomy can be revoked at any time.

## OSS integration boundary

Mastra, VoltAgent, and Vercel AI SDK are treated as implementation substrates behind VH-owned adapters. Security, authorization, identity, memory boundaries, and autonomy policy remain VH-owned. See `vendor/oss/ADAPTERS.md`.

The patch environment had no outbound network/DNS access, so upstream repositories could not be copied into the archive during this build. The adapter import manifests are included instead of pretending third-party source was vendored.
