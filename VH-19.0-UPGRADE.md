# Vouch Harbor 19.0.0 "Bastion" — upgrade notes

Base: 18.9.0 "Aurora". 19.0.0 is the oversight release: the bench grows
**300 → 460**, the domains get **AgentLeads that report directly to the
Generalist**, every sub-agent failure is now **classified with recovery
advice**, and the 18.9.0 review's last finding — the identity-cleanup
absolutes — is answered with an honest, probe-enforced **legacy-compat
registry**. Protocol unchanged at v0.10.7.

## 1 · AgentLeads — domain oversight that reports to the Generalist

`src/vh19/agentLead.ts`. Each of the ten domains now has a named lead
(`lead.code`, `lead.security`, …) with a mandate and its own playbook.
A lead (a) **plans domain work** across its real bench members (capped,
scored by routing vocabulary — a plan, not a wishlist), and (b) **reports
directly to the Generalist**: `buildLeadReport()` computes a structured
report — status (`completed / partial / planned / blocked`), per-member
outcomes, failures in words, and the single next step — **from the real
pipeline results, never asserted**. Like the goal engine, a lead calls no
provider and invents nothing. The report rides inside the provenance
digest, and the door shows it in the log: `PARTIAL · Code Domain Lead →
Generalist: 1 of 2 routed member(s) executed…`. `probe/agentLead` 26 checks.

## 2 · Failure taxonomy — errors handled like a product, not a shrug

`src/vh19/failures.ts`. Every non-execution is classified into a named
class — `no-provider · provider-auth · provider-rate-limit ·
provider-timeout · provider-unreachable · bad-response · gate-denied ·
policy-refused · injection-blocked · peer-refused · bad-input · unknown` —
each with severity (error vs honest info), a user-facing meaning, concrete
recovery advice, and a truthful retry verdict (`shouldRetry` is true only
for transient classes). Classification is attached centrally in the
generalist, so **every exit path carries it**, digest-sealed, and the door
renders the advice inline. An unclassifiable failure stays `unknown` —
never dressed up.

## 4 · Legacy isolation — the review's "absolutes" finding, answered

The 18.9.0 notes claimed "no legacy anywhere" while deliberate compat
identifiers remained. 19.0.0 replaces the absolute with a contract:
**`docs/LEGACY-COMPAT.md`** inventories every surviving legacy identifier
(old receipt formats, the offline-license secret name, `mjVersion` schema
field, legacy env-var fallbacks, native process/data-dir names, the storage
migration) with its reason and exit plan. **`probe/legacyCompat`** enforces
both directions: any legacy identifier outside the allowlist fails; any
allowlisted shim that vanishes from the tree or the docs fails. Active
surfaces were cleaned further: `VH_BROWSER_*` env vars now primary (legacy
honored), MCP client identity renamed, NOTICE/VENDOR/INSTALL/.editorconfig
rewritten to Vouch Harbor language.
